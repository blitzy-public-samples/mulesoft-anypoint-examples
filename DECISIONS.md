| D-082 | `importing-an-email-attachment-using-the-POP3-connector-java/pom.xml` carries a profile `single-test-selection`, active whenever the `test` property is set, that sets `jacoco.haltOnFailure` to `false`. A run that selects tests with `-Dtest`, such as the Tier 2A replay `mvn -B test -Dtest=FixtureParityTest` (0.7.2), still runs the JaCoCo `check` and prints any breach of the D-049 floor without failing; a full `mvn -B test` or `mvn -B clean install` enforces the floor | Enforce the floor on every run; add `-Djacoco.haltOnFailure=false` or `-Djacoco.skip=true` to the replay command by hand; drop the `check` execution | One selected test class covers only part of the `service` and `mapper` classes, so an enforced floor fails such a run whatever its test results, and the replay command of 0.7.2 is fixed without extra flags. The floor of D-049 describes the full suite, which still enforces it | Every `-Dtest` run, not only the replay, reports the floor without enforcing it. Passing `-Djacoco.haltOnFailure=true` on the command line restores enforcement for such a run. Coverage evidence comes only from the full `mvn -B test` and `mvn -B clean install` runs |
| D-083 | The seven Spring WS projects declare their SOAP runtime libraries explicitly beside `spring-ws-core`: `com.sun.xml.messaging.saaj:saaj-impl` (Boot-managed 3.0.4; compile scope in foreach-processing-and-choice-routing-java, soap-webservice-security-java, web-service-consumer-java and xml-only-soap-webservice-java, runtime scope in adding-a-new-customer-to-workday-revenue-management-java, legacy-modernization-java and service-orchestration-and-choice-routing-java) as the SAAJ implementation behind `SaajSoapMessageFactory`; and, in the six projects that marshal JAXB types (all except xml-only-soap-webservice-java, whose endpoints are DOM payload endpoints, D-029), `org.glassfish.jaxb:jaxb-runtime` (Boot-managed 4.0.5) at compile scope, with `jakarta.xml.bind-api` where declared. legacy-modernization-java uses `org.glassfish.jaxb.runtime.marshaller.NamespacePrefixMapper` from that runtime to write the `ns2` prefix its committed `reply.xml` shows | `spring-boot-starter-web-services`; relying on transitive artefacts (`spring-ws-core` 4.1.4 declares `jakarta.xml.soap-api` without a SAAJ implementation, and the JAXB runtime only at runtime scope); in legacy-modernization-java, rewriting namespace prefixes in an interceptor without a compile dependency on the JAXB runtime | `spring-boot-starter-web-services` pulls `jakarta.xml.ws:jakarta.xml.ws-api`, which the D-050 enforcer bans, and brings Tomcat back through `spring-boot-starter-web` (D-010). `WebServiceTemplate` and the Spring WS endpoints build messages through SAAJ, which needs an implementation at runtime. The Boot BOM pins both versions, and `com.sun.xml.messaging.saaj` lies outside the banned `com.sun.xml.ws:*`. `NamespacePrefixMapper` is a compile-time type, which the runtime-scoped copy does not provide | The SAAJ and JAXB runtime versions move with any Spring Boot BOM upgrade; legacy-modernization-java's prefix mapping couples its configuration to Glassfish JAXB internals |
